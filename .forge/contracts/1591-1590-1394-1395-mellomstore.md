### #1591 — podium-familien: dedupe presentasjon + rangert compute-retur (refactor)
Fil-hjem: `app/[locale]/games/[id]/leaderboard/podiumPresentation.ts` (har `PodiumPlace`,
`PodiumTier`, `PLACE_TIER`, `SLOT_HEIGHTS`). 13 filer bruker `TIER_ACCENT` lokalt (grep).
1. Flytt `TIER_ACCENT` (byte-identisk i alle) til `podiumPresentation.ts` som
   `export const TIER_ACCENT: Record<PodiumTier, string>`; slett de lokale kopiene og importer.
   Verifiser FØRST at alle 13 er identiske (`grep -A6 "TIER_ACCENT" …` per fil, diff) — er én
   ulik, la den stå med kommentar og nevn det i commit-body.
2. To høydeskalaer: 7 podier bruker delt `SLOT_HEIGHTS` (180/150/130), 5 (Nassau,
   TeamStableford, Shamble, TexasScramble, Patsome) bruker lokale 200/170/150 fordi de bærer
   en ekstra innholdslinje. Legg `export const SLOT_HEIGHTS_TALL` i `podiumPresentation.ts` med
   doc-kommentar (hvorfor: ekstra linje) og bytt de 5 lokale mappene til import.
3. NassauPodium medaljong 44/32 → 48/36 som de andre (bekreft at ingen kommentar/test
   begrunner avviket; hvis en gjør det → la stå + nevn).
4. Shamble/TexasScramble sorterer `result.teams` i podiet. Sjekk om computes i
   `lib/scoring/` allerede returnerer rangert (#1574 gjorde det for stableford-team/patsome).
   HVIS de ikke gjør det: `lib/scoring/AGENTS.md` = ny test FØRST (Type A: «returnerer
   lagene rangert») → gjør compute-returen rangert (samme mønster som #1574) → fjern
   call-site-sortering i de to podiene. HVIS de allerede gjør det: fjern bare den defensive
   sorteringen (og evt. legg én assert på eksisterende Type A-test). Egen commit for punkt 4.
Sikkerhetsnett: `npx vitest run "app/[locale]/games/[id]/leaderboard"` (én render-test per
podium fra #1573) + `lib/scoring` for punkt 4.

### #1394 — innboks-handlinger ruller tilbake ved feil; månedsbrev-bryteren sjekker skriving (fix)
1. `lib/notifications/markRead.ts` + `archive.ts`: la helperne returnere `Promise<boolean>`
   (`false` ved DB-feil, behold `console.error`; ikke kast — page-/after()-kallerne er best-
   effort og `void`-er). Oppdater typer, ikke oppførsel, hos øvrige kallere.
2. `app/[locale]/innboks/actions.ts`: `markOneAsRead`/`markAllAsRead`/`archiveOne`/`clearRead`
   returnerer `Promise<{ ok: boolean }>` (ok=false også når `userId` mangler).
   `toggleProductUpdates`: `.select('id')` + `expectAffected` (`lib/supabase/affectedRows.ts`,
   les signaturen) / eksplisitt error-sjekk → `{ ok: boolean }`.
3. `app/[locale]/innboks/InboxClient.tsx`: hver optimistiske handling tar snapshot av `items`
   før `setItems`, awaiter action-en inne i transition-en; ved `!ok` eller kast: `setItems(snapshot)`
   + vis en diskret feillinje (`<p role="status" data-testid="inbox-action-error">` med
   `t('actionFailed')` — ny nøkkel `inbox.actionFailed`: «Fikk ikke lagret — prøv igjen.» /
   "Couldn't save — try again."), som forsvinner ved neste vellykkede handling. Månedsbrev-
   bryteren (finn hvor `toggleProductUpdates` kalles — InboxClient eller søsken): samme
   rollback + feillinje.
4. Test: `InboxClient.test.tsx` finnes — legg til maks én `it` («feilende arkivering ruller
   kortet tilbake og viser feillinja»); Type A for `toggleProductUpdates`?—kun hvis
   `actions.test.ts` finnes; ellers ikke ny fil.
`.changes/1394-innboks-rollback.md` (fix): «Feiler lagringen når du rydder i innboksen eller
skrur av månedsbrevet, sier appen fra og setter alt tilbake — i stedet for å late som det gikk bra.»

### #1395 — dobbel avvisning sender ikke to varsler (fix)
`app/[locale]/games/[id]/approve/actions.ts` `rejectScorecard` (:207–232): UPDATE-en er
ufiltrert; #704-guarden behandler 0 rader som `?error=db`. Teknisk valg (ikke produktvalg —
brukeren ser bare at duplikat-varselet forsvinner):
- Legg til `.not('submitted_at', 'is', null)` på UPDATE-en (kun et innlevert kort kan avvises).
- 0 rader → skill legitim dobbel-avvisning fra RLS-nekt: `SELECT submitted_at` på samme rad
  (`game_players` er lesbar for deltakere — bekreft med policy-grep i `supabase/migrations`).
  Rad finnes med `submitted_at IS NULL` → kortet er allerede avvist: redirect til
  `?status=rejected` (idempotent suksess) UTEN varsel. Rad ikke synlig/finnes ikke → `?error=db`
  som før.
- Oppdater `actions.test.ts` (`describe('rejectScorecard')`): én ny case «allerede avvist →
  ingen ny notify, status=rejected»; behold #704-casen (0 rader + ingen rad → error=db).
`.changes/1395-dobbel-avvisning.md` (fix): «Trykker arrangøren «Avvis» to ganger på samme
scorekort, får spilleren nå ett varsel — ikke to.»
