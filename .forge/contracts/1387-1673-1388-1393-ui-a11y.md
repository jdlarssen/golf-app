## Design per issue

### #1387 — ScoreCard: fjern `role="button"` fra kort-div-en (fix)
`components/hole/ScoreCard.tsx` ca. :284–290: `<div role="button" aria-label=… aria-disabled=…
onClick={onCardClick}>` nester fire ekte `<button>` (Angre, +, −, ⋯) → ugyldig ARIA
(presentational children) og ikke tastatur-nåbar. Fiks:
- Fjern `role="button"`, `aria-label` og `aria-disabled` fra div-en. Behold `onClick={onCardClick}`
  (tapp-for-par er ren touch-bekvemmelighet; +/− dekker tastatur — fra tomt kort gir + par+1 og
  − par−1, se `onStepperPlus/Minus`).
- Legg `data-testid="score-card"` på div-en (tester/e2e trenger et håndtak når rollen er borte).
- Oppdater kommentar over div-en: hvorfor rollen er borte (WAI-ARIA presentational children,
  #1387) og at de nestede knappene bærer semantikken.
- Tester: `components/hole/ScoreCard.test.tsx:29` `querySelector('[role="button"]')` →
  `getByTestId('score-card')` (setup-helperen). `app/[locale]/games/[id]/holes/[holeNumber]/HoleClient.test.tsx:337`
  `getAllByRole('button', { name: /Sett score for/ })` → `getAllByTestId('score-card')`. Én ny
  assert i ScoreCard-testen: kortet har IKKE `role`-attributt og de fire knappene er `getAllByRole('button')`
  (kollaps-vern). Grep `e2e/` for `Sett score for` / `role="button"` mot ScoreCard — oppdater om treff.
- i18n-nøkkelen `setScoreAriaLabel` (`messages/no.json:2255` + en.json): fjern hvis den blir
  ubrukt (grep = 0 treff etter endringen), ellers la stå.
`.changes/1387-scorekort-tastatur.md`: «Skjermlesere og tastatur ser nå +/−-knappene på hvert
spillerkort direkte — kortet er ikke lenger én stor «knapp» som gjemmer dem.»

### #1673 — FormatGrid: synlig fokusring på valgt flis (fix)
`app/[locale]/admin/games/new/FormatGrid.tsx` ca. :70–90 (`if (selected)`-grenen): wrapperen har
`data-focus-inset` + `border-primary` + `shadow-[inset_0_0_0_1px_var(--primary)]`, og `<button>`
inni er flush mot topp/venstre/høyre. Den globale inset-regelen (`globals.css` `:where([data-focus-inset]) :focus-visible { outline-offset: -2px }`)
legger ringen (2 px, `--focus-ring` = `--primary` = #1b4332 i lys modus) rett inntil border+
inset-linje i samme farge → 4 px sammenhengende primary-blokk, ingen synlig ring.
- **IKKE** bruk `data-focus-surface="strong"` slik issuet først foreslår: det bytter ringen til
  `--bg-tint` (linen), som mot `--primary-soft` (#e8efe8) måler ~1,05:1 — enda verre.
- Fiks (issuets alternativ 2, gap-varianten): gi knappen i den valgte flisen en større negativ
  offset så ringen skilles fra border/inset-linjen med et gap av flisens egen fyll — Tailwind
  arbitrary property på knappen, f.eks. `focus-visible:[outline-offset:-5px]` (2 px ring, 3 px
  gap i `--primary-soft`; `:where(...)` har null spesifisitet så utility-en vinner). Kommentar
  ved knappen: hvorfor (#1673). Ikke rør globals.css.
- Verifiser: `npx vitest run app/[locale]/admin/games/new/FormatGrid.test.tsx` grønn (én assert
  kan legges til: valgt flis' knapp har klassen — kun hvis testen alt asserter klasser; ellers
  ingen ny test, dette låses av staging-skjermbildene). Staging: Tab til valgt flis på steg 2 i
  veiviseren, lys + mørk, skjermbilde viser ring adskilt fra kanten.
`.changes/1673-formatflis-fokusring.md`: «Tastaturfokus på det valgte spillformatet i veiviseren
har fått en tydelig ring.»

### #1393 — stale påmeldings-varsler arkiveres når de skjules (fix)
`app/[locale]/innboks/page.tsx` ca. :50–63 filtrerer bort `registration_request`-varsler for
slettede spill kun fra VISNINGEN; radene forblir uleste → bunn-nav-prikken (`hooks/useUnreadNotificationsCount.ts`
teller `read_at is null`) kan aldri slukkes. Fiks:
- `lib/notifications/staleNotifications.ts`: ny ren funksjon
  `partitionStaleSignupNotifications(rows, existingGameIds) → { visible, stale }` (samme
  predikat som `filterStaleSignupNotifications`; behold den eksisterende som tynn wrapper eller
  bytt call-siten — én regel, ett hjem). Type A-cases i `staleNotifications.test.ts`: tom, kun
  stale, blandet, andre kinder alltid visible.
- `page.tsx`: bruk partisjonen; er `stale.length > 0`, kjør best-effort i `after(async () => …)`
  (import fra `next/server`, presedens `app/[locale]/games/[id]/(home)/page.tsx:340`) én
  admin-client-update: `.from('notifications').update({ read_at: now, archived_at: now })
  .eq('user_id', userId).in('id', staleIds).is('archived_at', null)` — arkiver + lest i samme
  slengen (samme par som `archiveNotifications` én-rad-grenen bruker). Feil → `console.error('[innboks] archive stale failed', …)`,
  aldri kast. Kall `revalidateTag`-formen som `markRead.ts`/`archive.ts` bruker (les og speil).
  Legg helperen som `archiveStaleNotifications({ userId, ids })` i `lib/notifications/archive.ts`
  (admin-client, cookies-fri, jf. #726-kommentaren i markRead.ts) — IKKE inline i page.tsx.
- Oppdater doc-kommentaren i `staleNotifications.ts:32–34` («ikke-destruktivt … skjules bare» →
  «arkiveres best-effort av innboks-siden, #1393»).
- Realtime-hooken plukker opp UPDATE (`read_at` satt) → prikken slukker uten reload.
`.changes/1393-fantom-prikk.md`: «Den røde prikken på Innboks kunne henge igjen etter varsler om
spill som var slettet — nå forsvinner den når du åpner innboksen.»
