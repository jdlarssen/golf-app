## Problem

1. **#1783:** To skjema-parsere i `lib/cup/` diskriminerer resultatet ulikt:
   `parseCupPlanForm` (`planValidation.ts:112`) returnerer
   `{ ok: CupPlanValues } | { error: CupPlanError }` (konsumeres med `'error' in
   parsed`), mens `parseCupDraftForm` (#1778) og `SideAwardActionResult`
   (`sideAwardActions.ts:42`) bruker flagg-formen `{ ok: true, … } | { ok: false,
   error }`. Idiomet har to hjem; flagg-formen er repoets dominante (verifisert med
   grep 2026-08-29).
2. **#1782:** `executeAction` (`lib/loops/discordActions.ts:156`) har kompleksitet 44
   (grense 25) — én switch over seks custom_id-familier (`ready_issue`, `answer`,
   `drop_issue`, `snooze_issue`, `merge_pr`, `publish_lansering`) med ~190 linjer
   case-kropper. Eneste konsument: `app/api/discord/interactions/route.ts:215`.
   631 linjer eksisterende tester i `discordActions.test.ts` er sikkerhetsnettet.

## Design

### #1783 — flagg-formen samles (refactor, PR A)

- `parseCupPlanForm` endres til `{ ok: true, values: CupPlanValues } | { ok: false,
  error: CupPlanError }`. Alle feilkoder og første-feil-rekkefølgen er UENDRET —
  dette er en ren shape-endring.
- Konsumenten (`planActions.ts:174`, `'error' in parsed`-sjekken) oppdateres til
  flagg-sjekk. Grep etter flere konsumenter først (kjent: kun planActions).
- Interne hjelpere i `planValidation.ts` med samme to-hjem-form (f.eks.
  best-ball-parseren `{ ok: number | null } | { error }`) unifiseres når det er
  billig — byggerens skjønn, men modulen skal ikke ende halvt-og-halvt.
- Eksisterende tester for parseren OPPDATERES til den nye formen (shape-endringen er
  selve poenget — dette er det sanksjonerte unntaket fra «aldri endre eksisterende
  tester»; endringen skal være mekanisk: `.ok`/`.error`-aksess, ingen endrede
  forventede koder/verdier). Flagg endringen eksplisitt i rapporten.

### #1782 — dispatcheren dekomponeres (refactor, PR B — DRAFT, eier-gates)

- Én pure/injisert helper per custom_id-familie (seks stykker), hver med samme
  deps-injeksjonsmønster som i dag; `executeAction` blir tynn dispatch (parse +
  switch som delegerer). Mål: ingen funksjon i `lib/loops/` over 25 UNNTATT
  pre-eksisterende som ikke røres — dvs. `executeAction` ≤ 25 og hver helper ≤ 25.
- REN FLYTTING: signaturverifisering, custom_id-parsing, feilmeldinger (norsk
  bruker-copy i Discord-svar — behold ordrett), GitHub-kall og deps-kontrakten er
  bit for bit uendret. `executeAction`s eksporterte signatur er uendret
  (route.ts-konsumenten skal ikke røres).
- **Eksisterende tester (631 linjer) skal passere UMODIFISERT** — det er
  hovedbeviset på uendret oppførsel. Ingen nye tester kreves (dekningen finnes);
  legg KUN til tester hvis en helper får en observerbar kontrakt eksisterende
  suite ikke dekker (begrunn i rapporten).
- Helpers kan bo i samme fil eller egne filer under `lib/loops/` — byggerens skjønn
  (samme fil er minst diff; egne filer hvis fila ellers blir uleselig).

## Edge Cases & Guardrails

- #1783: `planActions`-flyten (saveCupPlan) er cup-admin-skrivestien — ingen endring
  i noen DB-kall, kun diskrimineringen. Ingen i18n-endring (kodene består).
- #1782: `merge_pr`-casen ER merge-porten — flytt den ordrett; en subtil endring der
  kan auto-merge feil PR. `publish_lansering` poster til Discord/tavla — samme
  varsomhet. Ingen endring i `autoMerge.ts` (egen modul, urørt).
- Begge: ingen `.changes/`-notat (refactor); `Refs #N` i hver commit.
- **PR B-mekanikk:** opprettes som draft og BLIR draft. Ingen `gh pr ready`, ingen
  merge fra økta. Kortet noop-er drafts, og sweepen fra #1769 rører kun
  `claude/natt-*` — draften er trygg for begge. Eieren merger selv fra PR-siden,
  eller sier «merge #<N>» i chatten (da flipper+merger en økt med det mandatet).

## Key Decisions

- Flagg-formen (`ok: true/false`) vinner — dominant i repoet; planValidation er
  avvikeren (#1783s eget forslag).
- #1782 gates på eieren fordi `lib/loops/` står på aldri-auto-merge-lista — koden
  bygges på stående mandat, men mergen er eierens (rettet prosess fra runde 2).
- PR A og PR B er separate så #1783 ikke må vente på eier-gaten.
